# RC003: SECURITY DEFINER function without a pinned search_path

**Severity:** high
**Standards:** CWE-426 · NIST SP 800-53 CM-6, AC-6 · CIS Controls v8 4.1

## What it catches

A `SECURITY DEFINER` function (callable or trigger) without `SET search_path`.

## Why it matters

When a function says `orders`, Postgres looks that name up using the caller's `search_path`. That includes the caller's own temporary schema, which every session can write to. A caller can create a temporary table or function with the same name as something the definer uses, and the definer will use theirs instead, with the owner's powers.

## How to fix

```sql
alter function public.your_function(uuid) set search_path = '';
```

With an empty `search_path`, refer to every table inside the function with its schema: `public.orders`, not `orders`. You can also set it when creating the function:

```sql
create function public.your_function(uid uuid) returns ...
language plpgsql security definer set search_path = '' as $$ ... $$;
```
