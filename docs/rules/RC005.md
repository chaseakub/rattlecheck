# RC005: Policy lets anyone change every row

**Severity:** high (change), warning (add, read)
**Standards:** CWE-732 · NIST SP 800-53 AC-3, AC-6 · CIS Controls v8 3.3

## What it catches

A permissive policy whose condition is simply `true`, for a role that can reach the table:

- **high:** `UPDATE`, `DELETE`, or `ALL` for `anon`, `authenticated`, or `public` (a policy without `TO` applies to everyone). Anyone can change other people's rows.
- **warning:** `INSERT` with `with check (true)`. Anyone can add rows. That's normal for a signup or contact form, but check that nobody can add a row that claims to belong to someone else.
- **warning:** `SELECT` for `anon` or `public`.

## Why it matters

Row-level security only protects a table as well as its policies do. `using (true)` admits every row, so for that action RLS might as well be off. "Enable RLS, then add `using (true)` to make the error go away" is one of the most common ways apps end up open.

Some of this is intended: a menu or store hours anyone can read, a waitlist anyone can join. That's why adding and reading are warnings, not failures.

## How to fix

Replace the policy with one scoped to the row's owner:

```sql
drop policy "your policy" on public.your_table;
create policy "your policy" on public.your_table
  for update to authenticated
  using ((select auth.uid()) = user_id)
  with check ((select auth.uid()) = user_id);
```

If a table is meant to be readable by everyone, allow it in `rattlecheck.config.json` with a reason.
